# Как участвовать в SkipIt

Перед работой прочитайте [инструкцию разработчика](docs/DEVELOPMENT.md).
SkipIt в этом репозитории — приложение для Windows.

## Ошибка или предложение

Для ошибки используйте форму Bug report, для идеи — Feature request.
Укажите версию SkipIt, версию Windows, шаги повторения и ожидаемый результат.
Уязвимости сообщайте приватно по [SECURITY.md](SECURITY.md).

Не публикуйте ссылки подписок, QR-коды доступа, UUID и пароли серверов, HWID,
реальные конфиги и адреса серверов. Перед отправкой снимка экрана включите
«Скрыть IP и ссылки» и проверьте изображение. Диагностический отчёт тоже просмотрите:
он может содержать адреса посещённых сайтов. Отправляйте только необходимые сведения.

## Подготовка pull request

1. Создайте отдельную ветку и ограничьте изменение одной задачей.
2. Используйте Flutter версии из `.github/workflows/build.yml`. Подготовьте ядра по инструкции разработчика.
3. Выполните `flutter pub get --enforce-lockfile`, `flutter analyze --no-pub`, `flutter test --no-pub`.
4. Для изменений поведения добавьте проверку, которая воспроизводит проблему или проверяет новый сценарий.
5. Изменения интерфейса проверьте глазами на минимальном размере окна и при разном масштабе Windows.
   В PR приложите изображения с условными данными. Автоматические отрисовки не заменяют проверку приложения.
6. Для изменений службы, оболочки или установщика проверьте соответствующую сборку и опишите ручную проверку.

Правила провайдера сохраняйте; не заменяйте полный JSON-конфиг одним выходом.
Новые тексты интерфейса оборачивайте в `tr(...)` и добавляйте перевод в `lib/l10n/en.dart`.
Версии программы и ядер не меняйте в посторонних исправлениях.

В описании PR укажите проблему, новое поведение, выполненные проверки и оставшиеся ограничения.
Пример адреса в тесте — `server.example` или `203.0.113.1`; используйте условные данные.
При изменении зависимостей обновляйте lock-файл намеренно и объясняйте причину.
