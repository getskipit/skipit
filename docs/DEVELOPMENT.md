# Разработка SkipIt

Этот файл — для разработчиков. Пользователям достаточно установщика из Releases.

Программа написана на Flutter (Windows), протоколы обрабатывает **Xray-core**. Режим TUN и правила
по приложениям — на выбор пользователя: сам Xray (по умолчанию, `XrayConfig.addTun`) или **sing-box**
(`lib\core\singbox_config.dart`). Ядра и `wintun.dll` (драйвер адаптера для Xray, берётся из его же архива)
кладутся в установщик при сборке.

## Сборка из исходников

Нужны [Flutter](https://docs.flutter.dev/get-started/install/windows/desktop) **3.47.5** (как в CI),
Visual Studio 2022 с нагрузкой «Разработка классических приложений на C++» и
[Inno Setup](https://jrsoftware.org/isdl.php).

```
flutter pub get --enforce-lockfile
flutter analyze --no-pub
flutter test --no-pub
powershell -ExecutionPolicy Bypass -File tools\build.ps1                     # программа + установщик
powershell -ExecutionPolicy Bypass -File tools\dev.ps1                       # тестовая копия «SkipIt Dev»
```

Без `-Version` скрипт берёт текущую версию из `lib/version.dart`; существующие номера версий не меняет.
Результат — `build\installer\SkipIt-Setup-Windows-<версия>.exe` и файл `.sha256` с его контрольной суммой.
Для новой копии репозитория перед тестами с ядром выполните `tools\setup.ps1`: ядра нужны части тестов.
Обязательность и сверка SHA-256 отдельно проверяются без сети: `tools\test-setup.ps1`.
Иконка пересобирается скриптом `tools\make_icon.ps1`.

CI использует Windows Server 2022, Flutter 3.47.5 и зависимости из `pubspec.lock`.
При смене Flutter обновляйте `FLUTTER_VERSION` в workflow вместе с этой инструкцией,
проверяйте lock-файл и выполняйте анализатор, тесты и сборку установщика.

### Что не хранится в Git

`.gitignore` исключает результаты сборки, кэш Flutter, настройки редакторов, журналы,
локальные ядра в `core/` и готовую программу в `dist/`. Ядра загружаются по `tools/cores.json`.
`pubspec.lock` и `.metadata` отслеживаются: они нужны для зависимостей и инструментов Flutter.
Личные рабочие заметки добавляйте в `.git/info/exclude` своего клона; этот файл не публикуется.
Исключения не удаляют уже отслеживаемые файлы и историю. Не добавляйте подписки, ключи,
HWID и реальные конфиги даже в примеры и тесты.

Установщик состоит из своей оболочки Win32 (`installer\shell`, C++) и вложенного Inno Setup
(`installer\skipit.iss`). Оболочка определяет язык Windows, даёт переключить EN / RU и запускает
Inno Setup без его мастера после согласия с лицензией. Копирование файлов, обновление и удаление
службы остаются в Inno Setup. `tools\build-installer.ps1` собирает обе части из уже собранной
программы и считает SHA-256 итогового файла; `tools\build.ps1` вызывает его автоматически.
Для просмотра интерфейса без установки: `tools\build-installer.ps1 -Preview`.
Такая сборка не содержит вложенного установщика, не запрашивает UAC и не может начать установку.

Тест `min_window_test.dart` отрисовывает каждую страницу в окне наименьшего размера. Чтобы посмотреть
на них глазами, сохраните картинки в папку:
`flutter test test\min_window_test.dart --update-goldens --dart-define=SKIPIT_SHOTS=C:\Temp\shots`.

### Тестовая копия

`tools\dev.ps1` собирает программу в `build\dev` и запускает её как **SkipIt Dev**. У неё всё своё:
папка данных `%APPDATA%\SkipIt Dev`, автозапуск, положение окна, имя TUN-адаптера. Поэтому её можно
запускать рядом со SkipIt, установленным из релиза, — они не мешают друг другу. При первом запуске
подписки и настройки один раз копируются из установленной программы. Из релизов тестовая копия не обновляется.

Служба SkipIt (`windows\service`, файл `skipit-service.exe`) работает с правами системы и принимает команды
только от `SkipIt.exe` из своей папки; установщик ставит её сам. Тестовой копии нужна своя служба
**SkipItDev**: `tools\dev-service.ps1` ставит или обновляет её (с ключом `-Uninstall` — снимает), окно UAC
скрипт покажет сам. Файл службы при этом копируется в `Program Files\SkipIt Dev Service`.

### Переносная сборка для локальной проверки

ZIP из уже собранной программы: `powershell -ExecutionPolicy Bypass -File tools\build-portable.ps1`.
Результат — `build\portable\SkipIt-Portable-Windows-<версия>.zip` и `.sha256`. Публичная сборка выпускается
установщиком. О переносном режиме см. [PORTABLE.md](PORTABLE.md).

### Версии ядер

Ядра вложены в установщик, программа у пользователей их сама не обновляет. Версии задаются в `tools\cores.json`:

```json
{ "xray": { "version": "v26.11.9", "sha256": "…" }, "sing-box": { "version": "v1.14.3", "sha256": "…" } }
```

`version` — тег релиза ядра на GitHub, `sha256` — обязательная контрольная сумма zip-архива для Windows x64 со страницы
релиза: 64 шестнадцатеричных знака. Без неё `setup.ps1` остановится до скачивания.
При скачивании сумма проверяется перед распаковкой; уже установленное ядро скрипт проверяет по версии,
а не по хэшу exe. Чтобы обновить ядро: поменяйте оба значения, запустите
`flutter test` (тест `xray_core_test.dart` проверит на новом ядре конфиги для всех видов ссылок и для TUN) и
выпустите новую версию SkipIt. У Xray свежие версии выходят с пометкой pre-release — это обычная
практика авторов, брать нужно их.

### Перевод интерфейса

Тексты в коде пишутся по-русски и оборачиваются в `tr('…')` (`lib/l10n/l10n.dart`), подстановки — `{0}`,
`{1}`: `tr('Порт {0} занят', [port])`. Английские строки лежат в `lib/l10n/en.dart`: ключ — русская строка
целиком. Тест `l10n_test.dart` находит в `lib` все русские строки и падает, если у какой-то нет перевода
(или подстановки не совпадают), — новую строку нужно добавить и в `en.dart`. Язык выбирается в
Настройки → Внешний вид → «Язык», по умолчанию — как в Windows.

## Выпуск версии

GitHub Actions (`.github/workflows/build.yml`) проверяет pull request в `main`, изменения `main`
и ручные запуски: зависимости по lock-файлу, анализатор, тесты, программа и установщик.
Проверочное задание имеет только право чтения репозитория. Файлы можно скачать из Actions → Artifacts.
Отдельное задание с правом записи публикует файлы только по событию публикации релиза
и только после успешной проверки и сборки.

1. **Releases → Draft a new release**, тег — `v` и номер версии: `v1.1.6`; предварительная версия — с буквой в конце
   (условно `vX.Y.Za`), а её следующие сборки — с номером через дефис: `vX.Y.Za-1`, `vX.Y.Za-2`
   (сначала сравниваются цифры, при равных — буква, потом номер сборки; версия без буквы новее версии с буквой,
   без номера сборки — старше сборок с номером: `X.Y.Za` < `X.Y.Za-1` < `X.Y.Zb` < `X.Y.Z`).
2. Галочку **pre-release** можно не трогать — сборка выставит её сама по номеру версии:
   буква в конце, с номером сборки или без (`vX.Y.Za`, `vX.Y.Za-2`) → pre-release, без буквы (`v1.1.6`) → обычный релиз.
   Кто что получает:
   - канал **«Бета»** — всегда самую свежую версию, включая пре-релизы;
   - канал **«Стабильный»** (по умолчанию) — только обычные релизы. Пока ни одного обычного
     релиза нет, он тоже получает пре-релизы — иначе пользователи в альфе остались бы без обновлений.
3. **Publish release.** Через несколько минут к релизу прикрепятся `SkipIt-Setup-Windows-<версия>.exe`,
   файл `.sha256` с его контрольной суммой и архив с исходниками вложенного sing-box (этого требует GPL),
   а установленные SkipIt предложат обновиться. Версия в программе берётся из тега.

Программа узнаёт о новой версии по обычным адресам GitHub (`/releases/latest`, `/releases.atom`,
`/releases/download/...`), а не через API: у API лимит 60 запросов в час на IP-адрес.

## Где программа хранит данные

`%APPDATA%\SkipIt`: `state.json` (настройки открыто; подписки и серверы — в поле `protected`,
зашифрованы DPAPI для учётной записи), папка `logs` (журнал: файл на каждое подключение, хранится
5 дней), geo-базы. Конфиги ядер на диск не пишутся — ядра получают их через стандартный вход;
тестовая копия «SkipIt Dev» дополнительно сохраняет `config.json` и `tun.json` для разбора неполадок.
Положение окна — в реестре `HKCU\Software\SkipIt`.

Флаги стран — [flagcdn.com](https://flagcdn.com) (общественное достояние).

Правила подготовки изменений — в [CONTRIBUTING.md](../CONTRIBUTING.md).
